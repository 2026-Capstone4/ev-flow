## P2 — 3~4주차

### API 명세 · 연동

| ID | 항목 | 담당 | 선택지 | 제안 · 비고 |
|---|---|---|---|---|
| API-01 | 명세서 전달 시점 · 형식 | 장승민 | FastAPI 자동 생성 OpenAPI(Swagger) / 별도 문서 | FE는 명세서를 받은 뒤 MSW · 타입 작성 시작. **전달 목표일 합의 필요** |
| API-02 | OpenAPI → TypeScript 타입 자동 생성 도입 | 장승민, 김무겸 | 도입 / 수동 작성 | FE 타입 수동 작성 · 불일치를 줄일 수 있음 |
| API-03 | 명세 변경 공유 절차 | 장승민, 김무겸 | — | 🟡 명세 변경은 PR로 올리고 FE 담당자에게 공유 |
| API-04 | 에러 응답 형식 공통 규약 | 장승민 | — | FE 경고 표시 · 재시도 처리에 필요 |
| API-05 | JSON 필드 이름 표기 | 장승민, 김무겸 | `snake_case` / `camelCase` | Python은 `snake_case`, TypeScript는 `camelCase`가 관례. 응답 표기와 변환 위치(백엔드 / 프론트엔드) 결정 필요 |
| COM-07 | 도메인 용어 영어 표기 확정 | 전원 | — | DB 컬럼 · API 필드 · 코드 이름에 공통 사용. 🟡 초안: [code-common.md 도메인 용어](conventions/code-common.md#도메인-용어) |

- 명세서에 포함되어야 하는 정보 (제안서 기준, FE 화면 요구사항):
  - 충전소 기본 정보, 위치, 급속 충전기 수, 현재 사용 가능 대수
  - 현재 혼잡도 및 30분 후 혼잡도(3단계), 혼잡 확률, 예상 가용 대수
  - 예상 대기 구간 (P50 · P90)
  - 추천 Top-3, 추천 점수, 추천 설명 근거 (최근접 대비 추가 이동시간, 충전 가능 확률 차이, 대기시간 감소분)
  - **데이터 갱신 시각, 예측 신뢰도, 결측 대체 여부** — 제안서상 사용자에게 표시해야 함
  - 운영자 대시보드: 충전소별 시간대 · 요일별 이용률 분포, 충전기 상태, 수집 상태 · API 지연 · 결측 현황
